 1. CRITICAL / HIGH

src/mainwindow.cpp:145-148  [CRITICAL]
    openFile() deletes iarMap/stMap but does not set them to nullptr. Pointers
    dangle. Scenario: open an IAR .map (iarMap = A), then open a .M66 (A deleted,
    iarMap still == A, stMap = B), then open any file -> "delete iarMap" deletes
    A a second time => double free / heap corruption. The same dangling pointer
    is deleted again in the destructor (mainwindow.cpp:84-88).
    Fix: set to nullptr after delete, or better use a single
    std::unique_ptr<XMap> (requires virtual destructor in XMap, see below).

src/iar_map.cpp:29 (used at :68)  [HIGH]
    'char chapter;' is uninitialized. Every line before the first "***" line is
    tested with 'if(chapter == 'E')' on an indeterminate value (undefined
    behaviour; random garbage parsing if it happens to be 'E').
    Fix: char chapter = '\0';

src/st_map.cpp:29-30 (used at :60, :67)  [HIGH]
    'chapter' and 'ch_line_idx' are uninitialized. Same undefined behaviour as
    above; ch_line_idx++ on an indeterminate value.

src/iar_map.cpp:52, src/st_map.cpp:49  [HIGH]
    strncpy_s(cline, 256, line.c_str(), line.length()) - if a line is >= 256
    characters the runtime-constraint is violated: with MSVC CRT the invalid
    parameter handler is called (default: process termination). Long C++
    mangled/demangled symbol names easily exceed 255 chars.
    Also MSVC/Annex-K specific (not portable).
    Fix: pass _TRUNCATE as count, or avoid the fixed buffer entirely and work
    on a std::vector<char>/std::string copy of the line.

src/utils.cpp:115  [HIGH]
    extractRest(): condition '(*ptr0 == ' ') && (*ptr0 == '\t')' is always false
    (a char cannot be both). Trailing whitespace is never removed, contrary to
    the documented behaviour. Should be '||'. Object names may therefore carry
    trailing blanks and object filtering / grouping compares unequal strings.

src/utils.cpp:145, :194; src/map_entry.h:43-44, :64-66, :87-89  [HIGH]
    'unsigned long' is 32 bit on Windows (LLP64). 64-bit addresses (IAR prints
    them as 0x0000'0000'0800'0000 - the apostrophe handling suggests this is
    expected) are silently truncated; hex digits beyond 8 are shifted out with
    no overflow detection. Sizes summed in codeSize/dataSize can also overflow.
    Fix: use uint64_t / unsigned long long and check digit count.

src/ConfFile.cpp:272  [HIGH]
    get_qstr() returns it2->second.varString directly, ignoring the object type.
    If the value was stored as an integer (set()) or was previously read via
    get() (which converts STRING->INTEGER and CLEARS varString, see :44-53) an
    empty string is returned. Use the 'operator string()' conversion instead.

src/ConfFile.cpp:44-53 / :58-68 (decl. ConfFile.h:41-42)  [HIGH]
    Conversion operators are non-const and destructive: converting to int
    erases the string representation and vice versa. Reading a value changes
    the stored value (e.g. a string "abc" read once as int becomes 0 forever and
    is written back as "0" to config.cfg). Conversions should be const and
    non-mutating.

src/mainwindow.cpp:151  [HIGH]
    fileName.toLatin1() - any path containing characters outside Latin-1
    (Cyrillic, CJK, many Eastern European letters, ...) is converted to '?' and
    the file cannot be opened. Additionally the parsers use narrow-char
    ifstream, which on Windows uses the ANSI code page.
    Fix: open with QFile/QTextStream, or pass a wide path
    (fileName.toStdWString()) to std::ifstream on Windows.

src/mainwindow.cpp:153-157  [HIGH]
    No error handling when the file cannot be opened or contains no recognised
    data: the parsers silently return (iar_map.cpp:38-39, st_map.cpp:39-40),
    empty tables are shown and the title shows the file name as if loaded.
    Show an error (AppInterface::MsgErr exists but is never used).

src/map_entry.h:78-90  [MEDIUM]
    XMap (base class) has no constructor (objCnt, codeSize, dataSize,
    unknownSize are uninitialized until a derived ctor sets them) and no
    virtual destructor - deleting a derived object through an XMap* (e.g.
    currMap) would be undefined behaviour. All data members are public.

src/map_entry.h:29-40  [MEDIUM]
    Anonymous struct inside a union is a compiler extension (not ISO C++,
    warns with -pedantic). Writing 'valid.value' and reading bit fields is
    union type-punning (UB in C++). Use plain bool members or std::bitset.

src/AppInterface.h:21-22 / src/AppInterface.cpp:18-21  [MEDIUM]
    in_loadWidgetGeometry and wid_loadWidgetGeometry are not initialized in the
    constructor. saveWidgetGeometry() reads them; if it is ever called before
    loadWidgetGeometry() -> undefined behaviour.

src/AppInterface.cpp:19  [MEDIUM]
    Configuration file "config.cfg" is a relative path -> depends on the current
    working directory (shortcut "Start in", drag&drop on exe, command line).
    Settings get lost/scattered, and writing fails silently in read-only dirs
    (e.g. Program Files). Use QSettings or QStandardPaths::AppConfigLocation.

src/AppInterface.cpp:39-42  [MEDIUM]

    keeps its old value (e.g. Minimized=1 and Maximized=1 can both be stored).
    Saving "Minimized" also makes the application start minimized next time,
    which is usually unwanted.

src/AppInterface.cpp:65-71  [MEDIUM]

    removing a monitor or changing resolution the window can open off-screen.

    and maximized state).

src/AppInterface.cpp:136, :159  [MEDIUM]

================================================================================
 RESOLUTION (2026-11-18)
================================================================================
Original sources backed up to: src_backup_before_fixes/
Verified: builds with MSVC 2010 + Qt 5.1.1 (release + debug, no compiler
warnings); parser output on map_examples/templproj.map identical to the
original version; GUI behaviour checked with an automated test harness.

FIXED - all CRITICAL, HIGH, MEDIUM, LOW and INFO items, except as noted below.
Main structural changes:
  - MainWindow owns the map via std::unique_ptr<XMap> (double delete gone).
  - Parsers: parse(std::istream&) instead of parsing in the constructor;
    state initialized; no fixed 256 char buffer; shared code moved into
    XMap::addEntry()/isValidSymbolName(); 64 bit MapValue for addr/size.
  - New map_loader.*: format detection by content (fallback: extension).
  - New map_models.*: QTableView + models replace QTableWidget items
    (numeric sorting, "< All >" pinned on top, one filter function,
    added "Unknown" column).
  - ConfFile stores plain strings (no destructive conversions), explicit
    load()/save() with QSaveFile; config moved to the user's app data
    directory (old config.cfg is migrated automatically on first start).
  - Window geometry via saveGeometry()/restoreGeometry().
  - Ctrl+F / F3 via QShortcut (application-wide event filter removed).
  - Errors are shown for unreadable / unsupported files; status bar shows
    symbol count and "not found" messages.
  - File given on the command line is opened.
